## 이 글에서 이해할 것

`new`로 힙에 메모리를 직접 빌리고 `delete`로 반납한다는 것, 그리고 `delete`에는 값(`*p`)이 아니라 주소(`p`)를 줘야 한다는 것.

## 읽기 전 최소 배경

포인터를 안다고 가정한다. `p`는 주소를 담고, `*p`는 그 주소 안의 값이다. (이게 안 잡혀 있으면 이 글 내내 헷갈린다 — 실제로 내가 그랬다.)

## 내가 막혔던 점 / 틀린 가설

두 군데서 크게 막혔다.

첫째, `delete`에 뭘 줘야 하는지. 나는 "메모리를 지우는 거니까 값 `*p`를 준다"고 생각하고 `delete *p;`라고 썼다. 에러가 났다.

둘째, 함수 안에서 `new`한 걸 다른 함수에서 `delete`하는 게 말이 되는지. "some()에서 만들었는데 main()에서 지운다고? 그럼 some()이 끝날 때 사라지는 거 아냐?" 하고 한참 헤맸다.

## 확인한 증거

먼저 `delete *p`가 왜 안 되는지 직접 쳐봤다.

```cpp
int* p = new int;
*p = 10;
delete *p;   // ← 에러
```

에러가 났다. 그래서 `p`와 `*p`가 실제로 뭐가 다른지 출력해봤다.

```cpp
int* p = new int;
*p = 10;
cout << p << endl;    // 0x562a3f8c2e70  (주소, 16진수)
cout << *p << endl;   // 10            (값)
```

직접 돌린 출력: 첫 줄은 이상한 16진수(주소), 둘째 줄은 10(값). 둘이 전혀 다른 게 눈에 보였다. `delete`는 "이 주소의 창고를 반납해줘"라는 뜻이니까, 주소를 담은 `p`를 줘야 하고 값인 `*p`를 주면 안 된다.

그다음, 함수에서 만들어 main에서 지우는 코드를 직접 돌렸다.

```cpp
#include <iostream>
using namespace std;

int* some()
{
    int* a = new int;
    *a = 5;
    return a;        // 주소를 돌려줌 (별표 없이)
}

int main()
{
    int* p = some();
    cout << *p << endl;   // 5
    delete p;
    return 0;
}
```

직접 돌린 출력: `5`. some()이 이미 끝났는데도 값이 살아있었다.

## 그래서 이렇게 이해했다

`new`로 만든 메모리는 힙에 있는 "내가 직접 빌린 창고"다. 자동 변수(`int a = 5;`)는 `{ }`를 벗어나면 알아서 사라지지만, 힙 창고는 내가 `delete`로 반납하기 전까지 안 사라진다. 그래서 함수가 끝나도 살아있다.

`p`는 그 창고의 열쇠(주소)고, `*p`는 창고 안의 물건(값)이다. `delete`는 창고 자체를 반납하는 거라 열쇠(`p`)가 필요하다. 물건(`*p`)을 내밀면 "이 물건을 반납해줘"가 돼서 말이 안 된다.

some()에서 `new`하고 main에서 `delete`하는 것도 괜찮다. `new`를 한 번 했으니 창고는 하나뿐이고, `a`와 `p`는 같은 창고를 가리키는 열쇠 두 개일 뿐이다. some()이 끝나며 `a`는 사라져도 창고는 남고, 그 주소가 `p`로 넘어왔으니 main에서 계속 쓰다 `delete p` 한 번으로 반납하면 된다.

나만의 규칙: **값을 다룰 땐 **`*p`**(별표 O), 메모리 자체를 다룰 땐 **`p`**(별표 X). delete는 창고를 다루니 **`p`**. 그리고 new 한 번 = delete 한 번.**

## 다른 예시에 적용해보기

만약 some()에서도 `delete a`를 하고 main에서도 `delete p`를 하면 어떻게 될까?

```cpp
int* some()
{
    int* a = new int;
    *a = 5;
    delete a;     // 여기서 반납하면?
    return a;
}
```

창고는 하나인데 같은 창고를 두 번 반납하는 꼴(이중 해제)이라 에러가 난다. 열쇠가 `a`, `p` 둘이어도 창고는 하나니까, `delete`는 한 번만 해야 한다. 그래서 빌려준 some()은 그냥 주소만 넘기고, 실제로 쓰는 main이 다 쓴 뒤에 한 번 반납한다.
