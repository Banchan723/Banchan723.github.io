## 이 글에서 이해할 것

클래스가 설계도고 객체가 그걸로 찍어난 실제 물건이라는 것, 그리고 생성자·소멸자·this가 각각 언제 쓰이는지.

## 읽기 전 최소 배경

변수와 함수가 뭐인지, 함수가 만들 때·끝날 때 실행된다는 개념을 안다고 가정한다. 지역변수는 `}`를 만나면 사라진다는 것도.

## 내가 막혔던 점 / 틀린 가설

생성자에서 `hp = hp;`라고 쓰면 멤버 hp에 들어갈 줄 알았다. 그리고 소멸자 출력 순서를 "생성 → 소멸 → 게임중"일 거라고 예상했다.

## 확인한 증거

먼저 생성자. 객체를 만드는 순간 자동으로 실행되는 초기화 함수다. 이름이 클래스명과 같고 리턴 타입이 없다.

```cpp
#include <iostream>
using namespace std;

class Monster
{
public:
    int hp;

    Monster()        // 생성자 (클래스랑 이름이 똑같음, 리턴 타입 없음)
    {
        hp = 100;    // 만들 때 자동으로 hp = 100
    }
};

int main()
{
    Monster m;       // 이 순간 생성자 자동 실행 → hp = 100
    cout << m.hp;    // 100 (직접 설정 안 했는데!)
    return 0;
}
```

직접 돌린 출력: `100`. `m.hp`를 직접 설정하지 않았는데도 생성자가 자동으로 채웠다.

객체마다 다른 값을 주려면 생성자가 값을 받게 한다.

```cpp
class Monster
{
public:
    int hp;
    Monster(int startHp)   // 만들 때 값을 받는 생성자
    {
        hp = startHp;
    }
};

int main()
{
    Monster a(100);   // hp 100짜리
    Monster b(50);    // hp 50짜리
    cout << a.hp << " " << b.hp << endl;   // 100 50
}
```

직접 돌린 출력: 넘긴 값으로 hp가 각각 정해졌다(a=100, b=50).

다음은 소멸자. 생성자와 소멸자에 둘 다 cout을 찍고 돌렸다.

```cpp
class Monster
{
public:
    Monster()  { cout << "몬스터 생성!" << endl; }   // 만들 때
    ~Monster() { cout << "몬스터 소멸!" << endl; }   // 사라질 때
};

int main()
{
    Monster m;
    cout << "게임 중..." << endl;
    return 0;
}   // ← 여기서 m이 사라짐 → 소멸자 실행
```

직접 돌린 출력 순서: `몬스터 생성!` → `게임 중...` → `몬스터 소멸!`. 소멸자는 객체가 사라질 때 불린다. `m`은 main의 지역변수라 main이 끝나는 `}`에서 사라지고, 그때 소멸자가 실행된다.

마지막, this. 매개변수와 멤버 변수 이름이 같을 때 문제가 생긴다.

```cpp
class Monster
{
public:
    int hp;
    Monster(int hp)    // 매개변수 이름이 hp (멤버랑 같음)
    {
        hp = hp;       // this 안 씀
    }
};

int main()
{
    Monster m(100);
    cout << m.hp;      // ?
}
```

직접 돌린 출력: `0`. `100`을 넣으려 했는데 0이 나왔다. `hp = hp;`에서 양쪽 다 가까운 매개변수 hp를 가리켜서 멤버 hp는 손도 안 닿은 것이다. 한 줄만 고쳐다.

```cpp
this->hp = hp;     // this->hp(멤버) = hp(매개변수)
```

고치고 다시 돌리니 `100`이 나왔다. `this->hp`는 "지금 이 함수를 부른 객체의 hp"를 명시하는 것이다.

## 그래서 이렇게 이해했다

클래스는 설계도(붕어빵 틀)이고, 객체는 그걸로 찍어난 붕어빵이다. 틀은 하나지만 찍어난 붕어빵은 각자 독립이라, `a.hp = 100` 해도 `b.hp`와는 상관없다.

생성자는 만들 때 자동 실행되는 초기화 함수다. 기본 생성자(`Monster()`)는 정해진 값으로, 매개변수 생성자(`Monster(int hp)`)는 만들 때 받은 값으로 채운다. 소멸자(`~Monster()`)는 객체가 사라질 때 자동 실행된다.

this->는 평소엔 안 써도 된다. 멤버 함수에서 그냥 `hp`라 쓰면 자동으로 자기 객체의 hp다. this->가 꼭 필요한 건 매개변수와 멤버 이름이 같을 때뿐이다. 그래서 이름을 다르게 지으면 this를 직접 쓸 일이 거의 없다.

## 다른 예시에 적용

언리얼에서는 생성자와 `BeginPlay()`는 자주 보이지만 일반 소멸자(`~AMonster()`)는 거의 안 쓴다. 소멸 쪽 로직은 `EndPlay()`나 `Destroyed()` 같은 엔진 생명주기 함수에 넣는다. 원리는 소멸자와 같은 "사라질 때 자동 실행"이다.

## 아직 모르는 것
