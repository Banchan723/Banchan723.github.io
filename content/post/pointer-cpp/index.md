## 이 글에서 이해할 것

포인터가 무엇이고, `*p`·`p`·`&p`가 각각 뭘 가리키는지, 그리고 포인터를 통해 구조체 멤버를 어떻게 쓰는지를 직접 친 코드로 확인한다.

## 읽기 전 최소 배경

이 정도는 안다고 가정한다.

- 변수 선언과 대입 (`int x = 100;`)
- `std::cout` 으로 값을 출력하는 법
- 구조체(`struct`)에 멤버가 있다는 것 (`.`으로 접근)

## 내가 막혔던 점 / 틀린 가설

공부하다 실제로 멈췄던 지점이다. 매끄럽게 정리하기보다 막힌 순서대로 적는다.

- **"포인터가 8바이트면 그게 오히려 낭비 아닌가?"** — 포인터를 쓰면 메모리를 아낀다고 들었는데, 포인터 자체가 8바이트나 한다. `int`는 4바이트인데 더 쓰는 거 아닌가. 이게 제일 안 풀렸다.
- **`*p` 랑 그냥 `p` 는 뭐가 다른가?** — 둘 다 `p`가 들어가는데 별(`*`)이 붙고 안 붙고로 의미가 달라진다는 게 처음엔 안 잡혔다.
- **가리키는 게 구조체면 멤버 접근은 어떻게 하나?** — 평소엔 점(`.`)으로 멤버를 쓰는데, 포인터일 땐 점이 안 먹힌다고 해서 막혔다.

## 확인한 증거

말로만 보면 안 잡혀서 최소 코드로 직접 돌렸다.

### 코드 1 — `p`, `*p`, `&p` 의 차이

```cpp
#include <iostream>

int main() {
    int x = 100;
    int* p = &x;     // p 에 x의 주소를 담는다 ( & = 주소연산자 )

    std::cout << p   << "\n";   // p   : x가 사는 주소
    std::cout << *p  << "\n";   // *p  : 그 주소로 찾아간 값 = x
    std::cout << &p  << "\n";   // &p  : p 자신이 사는 주소

    *p = 50;                    // 그 주소로 가서 값을 바꾼다 → x 가 바뀐다
    std::cout << x   << "\n";   // x   : 바뀐 값
    return 0;
}
```

> ⚠️ 직접 돌린 출력 채우기: (사용자가 g++로 컴파일·실행한 실제 출력을 여기에 붙여넣기. 환경 의존값인 주소는 그대로보다 "예: 0x..." 관계 중심으로 — `p`와 `&x`가 같은지, `*p`가 100→50으로 바뀌는지, `&p`가 다른 주소인지를 보면 된다.)

### 코드 2 — 구조체 멤버 접근

```cpp
#include <iostream>

struct Player {
    int hp;
};

int main() {
    Player p1;
    p1.hp = 100;        // 변수에 직접 → 점(.)

    Player* ptr = &p1;
    ptr->hp = 50;       // 포인터를 통해 → 화살표(->)
    // ptr->hp 는 (*ptr).hp 의 줄임말이다.

    std::cout << p1.hp        << "\n";   // ptr->hp 로 바꾼 값이 p1 에 반영됐는지
    std::cout << (*ptr).hp    << "\n";   // ptr->hp 와 같은 값인지
    return 0;
}
```

> ⚠️ 직접 돌린 출력 채우기: (사용자가 g++로 컴파일·실행한 실제 출력을 여기에 붙여넣기. `ptr->hp = 50`이 `p1.hp`에 반영되는지, `ptr->hp`와 `(*ptr).hp`가 같은 값을 주는지를 확인.)

## 그래서 이렇게 이해했다

막힌 점 세 개를 코드와 연결해 정리한다.

**① 8바이트 낭비 의문 — 경우를 나눠야 했다.**
내 의심이 틀린 게 아니라 조건을 안 본 거였다. `int`(4바이트)를 가리키려고 포인터(8바이트)를 쓰면 오히려 더 크다. 낭비 맞다. 반대로 큰 구조체를 함수에 넘길 때는 통째로 복사하는 대신 주소 8바이트만 넘길 수 있다. 즉 메모리 이득은 가리키는 대상이 포인터보다 클 때만 생긴다.

**② `*p` 와 `p` — 코드 1로 정리한 규칙.**
출력을 보고 안 헷갈리려고 내 식으로 규칙을 정했다.

- `p` = 주소 그 자체 (`&x`와 같음)
- `*p` = 그 주소로 찾아간 값 (역참조). `*p = 50` 하면 `x`도 바뀐다.
- `&p` = `p` 자신이 사는 주소 (가리키는 곳과 다른 곳)

**③ 포인터로 멤버 접근 — `->`.**
점은 변수에 직접, 화살표는 포인터를 통해서. 코드 2에서 `ptr->hp`와 `(*ptr).hp`가 같은 값을 줬다. 즉 `->`는 `*`로 먼저 찾아간 다음 `.`으로 멤버를 쓰는 걸 한 기호로 줄인 것이다.

## 다른 예시에 적용해보기

함수가 받은 값을 바꿔서 호출한 쪽에도 반영하고 싶을 때 포인터를 쓴다. 값으로 넘기면 복사본만 바뀌지만, 주소를 넘기면 `*`로 원본을 직접 고친다.

```cpp
#include <iostream>

void addTen(int* n) {
    *n = *n + 10;   // 받은 주소로 찾아가 원본을 직접 바꾼다
}

int main() {
    int score = 100;
    addTen(&score);              // score 의 주소를 넘긴다
    std::cout << score << "\n";  // 110 이 나오는지
    return 0;
}
```

> ⚠️ 직접 돌린 출력 채우기: (`addTen`에 주소를 넘겼을 때 `score`가 110으로 바뀌는지 확인. 만약 `int n`으로 값만 넘겼다면 100 그대로일 것 — 직접 바꿔서 비교해보면 차이가 분명하다.)

## 아직 모르는 것

이번 글에서 확인 안 한 것들. 나중에 따로 볼 것.

- `new` / `delete` 로 직접 메모리를 잡고 푸는 동적 할당
- 포인터를 가리키는 포인터(이중 포인터, `int**`)
- `nullptr` 과, 가리키는 대상이 없는 포인터를 `*`로 접근하면 어떻게 되는지(안전성)
- 스마트 포인터(`unique_ptr`, `shared_ptr`) — `new`/`delete`를 대신 관리해 준다고만 들었고 아직 안 씀
- 포인터와 배열의 관계, 포인터 산술(`p + 1`이 몇 바이트 이동하는지)
