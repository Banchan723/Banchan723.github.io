> 이 글은 혼자 공부하며 이해한 것을 정리한 **학습 노트**입니다. 틀린 부분이 있을 수 있어요.

지금 내 이해: 포인터는 어떤 변수가 **사는 주소를 담는 변수**고, `*`로 그 주소에 찾아가 값을 읽거나 바꾼다. 이번에 확인한 건 거기까지다.

## 내가 막혔던 점

공부하다 실제로 멈췄던 지점들. 매끄럽게 정리하기보다, 막힌 순서대로 적는다.

- **"포인터가 8바이트면 그게 오히려 낭비 아닌가?"** — 포인터를 쓰면 메모리를 아낀다고 하는데, 포인터 자체가 8바이트나 한다. `int`는 4바이트인데. 그럼 더 쓰는 거 아닌가? 이게 제일 안 풀렸다.
- **`*p` 랑 그냥 `p` 는 뭐가 다른가?** — 둘 다 `p`가 들어가는데 별(`*`)이 붙고 안 붙고로 의미가 달라진다는 게 처음엔 안 잡혔다.
- **가리키는 게 클래스/구조체면 멤버 접근은 어떻게 하나?** — 평소엔 점(`.`)으로 멤버를 쓰는데, 포인터일 땐 점이 안 먹힌다고 해서 막혔다.

## 확인한 코드

말로만 보면 안 잡혀서 최소 예제로 직접 확인했다.

```cpp
#include <iostream>

int main() {
    int x = 100;
    int* p = &x;     // p 에 x의 주소를 담는다 ( & = 주소 )

    std::cout << p   << "\n";   // p   : x가 사는 주소
    std::cout << *p  << "\n";   // *p  : 그 주소로 찾아간 값 = x
    std::cout << &p  << "\n";   // &p  : p 자신이 사는 주소

    *p = 50;                    // 그 주소로 가서 값을 바꾼다 → x 가 바뀐다
    std::cout << x   << "\n";   // x   : 50
    return 0;
}
```

구조체일 때 멤버 접근:

```cpp
struct Player {
    int hp;
};

Player p1;
p1.hp = 100;        // 변수에 직접 → 점(.)

Player* ptr = &p1;
ptr->hp = 50;       // 포인터를 통해 → 화살표(->)
// ptr->hp 는 (*ptr).hp 의 줄임말이다. 같은 동작.
```

## 결과 / 동작

> 로컬에 컴파일러가 없어서 진짜 출력값은 아직 못 채웠다. 구체 주소값(0x... 같은 건)은 실행마다 달라지니 적지 않는다. 대신 **표준이 보장하는 관계**로 적어둔다. 나중에 직접 돌려서 값은 채울 것.

이 코드를 돌리면 이렇게 동작한다.

- `&x` 와 `p` 는 **같은 주소**다. `p`에 `&x`를 넣었으니 당연.
- `*p` 는 **x의 값**이다. 처음엔 `100`, `*p = 50` 뒤엔 `x`도 `50`이 된다.
- `&p` 는 `p` 자신이 사는 **또 다른 주소**다. `x`가 사는 곳(`p`가 가리키는 곳)과는 다르다.
- `ptr->hp` 와 `(*ptr).hp` 는 항상 같은 값을 준다.

주소값 숫자 자체는 실행할 때마다 달라진다. 하지만 위 **관계는 어느 환경에서 돌려도 항상 같다**. 그래서 숫자가 아니라 관계로 기억하기로 했다.

## 그래서 이렇게 이해했다

막힌 점 세 개를 각각 정리하면.

**① 8바이트 낭비 의문 — 경우를 나눠야 했다.**
내 의심이 틀린 게 아니라 조건을 안 본 거였다.

- `int`(4바이트)를 가리키려고 포인터(8바이트)를 쓰면 → 오히려 더 크다. 낭비 맞다.
- 800바이트짜리 구조체를 함수에 넘긴다면 → 값으로 넘기면 800바이트를 복사하지만, 포인터로 넘기면 주소 8바이트만 넘어간다.

→ **메모리 이득은 가리키는 대상이 포인터보다 클 때만 생긴다.** 작은 값은 그냥 값으로 쓰는 게 낫다.

**② `*p` 와 `p` — 별이 붙고 안 붙고.**
안 헷갈리려고 내 식으로 규칙을 정했다.

- `p` = 주소 그 자체
- `*p` = 그 주소로 찾아간 값 (역참조)
- `&p` = `p` 자신이 사는 주소

**③ 포인터로 멤버 접근 — `->`.**
점은 변수에 직접, 화살표는 포인터를 통해서. `ptr->hp`는 `(*ptr).hp`의 줄임말일 뿐이다. 즉 ②의 `*`로 먼저 찾아간 다음 `.`으로 멤버를 쓰는 것과 같고, 그걸 한 기호로 줄인 게 `->`다.

## 아직 모르는 것

이번 글에서 확인 안 한 것들. 나중에 따로 볼 것.

- `new` / `delete` 로 직접 메모리를 잡고 푸는 동적 할당
- 포인터를 가리키는 포인터(이중 포인터, `int**`)
- `nullptr` 과, 가리키는 대상이 없는 포인터를 `*`로 접근하면 어떻게 되는지(안전성)
- 스마트 포인터(`unique_ptr`, `shared_ptr`) — 위 `new`/`delete`를 대신 관리해 준다고만 들었고 아직 안 씀
- 포인터와 배열의 관계, 포인터 산술(`p + 1`이 몇 바이트 이동하는지)
