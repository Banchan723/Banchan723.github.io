## 이 글에서 이해할 것

참조(`&`)가 변수의 별명이라는 것, 그리고 참조가 진짜 빛나는 자리는 함수 매개변수라는 것.

## 읽기 전 최소 배경

변수는 값을 담는 상자이고, 함수에 값을 넘기면 보통 복사본이 넘어간다는 것을 안다고 가정한다.

## 내가 막혔던 점 / 틀린 가설

`int& b = a`처럼 같은 자리에서 별명을 만드는 게 쓸모없어 보였다. 그냥 `a`를 쓰면 되는데 왜 별명을 만드나 싶었다.

## 확인한 증거

먼저 별명이 진짜 원본과 연결되는지 확인했다.

```cpp
#include <iostream>
using namespace std;

int main()
{
    int a = 50;
    int& b = a;   // b는 a의 별명
    b = 100;      // 별명을 바꾸면...
    cout << a << endl;   // 100! 원본도 바뀜
    return 0;
}
```

직접 돌린 출력: `100`. `b`가 `a`의 별명이니까 `b`를 바꾸면 `a`도 바뀐다.

그런데 같은 자리에서 별명을 만드는 건 별 쓸모가 없어 보인다. 참조가 진짜 빛나는 건 함수에 넘길 때다.

```cpp
#include <iostream>
using namespace std;

void addOne(int& x)   // 참조로 받음 = x는 넘어온 변수의 별명
{
    x = x + 1;        // 별명을 바꾸면...
}

int main()
{
    int a = 5;
    addOne(a);          // a를 넘김
    cout << a << endl;  // 6! 함수가 원본 a를 직접 바꿈
    return 0;
}
```

직접 돌린 출력: `6`. 함수에 참조로 넘기면 함수 안에서 바꾼 게 원본에 그대로 반영된다. `addOne` 안의 `x`가 사실 `main`의 `a`니까(별명이니까).

만약 참조 없이 `void addOne(int x)`로 받았으면, `a`의 복사본이 넘어가서 함수 안에서 아무리 바꿔도 원본 `a`는 5 그대로다.

확인 문제로 둘을 한 번에 비교했다. `changeA`는 값으로(`int x`), `changeB`는 참조로(`int& y`) 받아서 각각 99로 바꾼 뒤 원본을 출력했다.

직접 돌린 출력: `a = 1 b = 99`. `a`는 복사본이 넘어가 함수 안에서만 99가 됐다가 끝나니 원본은 1, `b`는 별명이라 함수 안에서 바꾼 99가 원본에 남았다.

## 그래서 이렇게 이해했다

참조(`&`)는 변수의 별명이다. 별표 없이 그냥 이름처럼 쓰고, 별명을 바꾸면 원본도 바뀐다.

가장 흔한 쓰임은 함수 매개변수다. 함수가 원본을 직접 바꿔야 하면 참조로 받는다. 값으로 받으면 복사본만 바뀌어서 원본은 그대로다. 추가로, 큰 데이터(덩치 큰 객체)는 값으로 넘기면 통째로 복사되니 비용이 큰데, 참조로 넘기면 복사 없이 원본을 바로 가리켜서 빠르다.

`&`가 두 가지 뜻으로 쓰여서 헷갈렸는데, 구분이 됐다. `int& b = a`에서의 `&`는 "참조"라는 뜻이고, `&a`처럼 변수 앞에 붙는 `&`는 "주소를 꺼내라"는 뜻이다. 위치가 다르다.

## 다른 예시에 적용

포인터로도 함수가 원본을 바꿀 수 있다. 차이는 표기다. 포인터는 `*`로 값을 꺼내야 하고(`*p = 6`), 참조는 별표 없이 그냥 이름처럼 쓴다(`x = 6`). 원본을 바꾼다는 목적은 같지만, 참조 쪽이 문법이 더 단순하다.

## 아직 모르는 것

여러 값을 한 번에 반환하는 방법(struct나 pair로 묶어서 하나로 반환), 그리고 `const` 참조(바꾸지 않으면서 복사도 피하는 방법)는 아직이다.
